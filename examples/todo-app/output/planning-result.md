# 투두앱 제품 기획서 (PRD)

## 1. 제품 개요

### 1.1 제품 비전
사용자가 일상의 할 일을 직관적으로 관리하고, 우선순위와 마감일 기반으로 효율적으로 업무를 처리할 수 있는 개인 태스크 관리 웹 애플리케이션

### 1.2 목표 사용자
- 개인 할 일 관리가 필요한 일반 사용자
- 학업/업무 태스크를 체계적으로 관리하고 싶은 학생 및 직장인

### 1.3 핵심 가치
- **심플함**: 복잡한 학습 없이 즉시 사용 가능
- **효율성**: 우선순위·마감일 기반 태스크 정렬로 중요한 일에 집중
- **신뢰성**: 데이터 유실 없는 로컬 영속 저장

## 2. 핵심 기능 목록

### 2.1 CRUD (기본 태스크 관리)

| 기능 | 설명 | 우선순위 |
|------|------|----------|
| **Create** | 새로운 투두 항목 생성 (제목 필수, 설명 선택) | P0 |
| **Read** | 전체 투두 목록 조회 및 개별 상세 보기 | P0 |
| **Update** | 투두 제목, 설명, 우선순위, 마감일, 완료 상태 수정 | P0 |
| **Delete** | 개별 투두 삭제 및 완료 항목 일괄 삭제 | P0 |

### 2.2 태스크 속성

| 속성 | 타입 | 필수 여부 | 설명 |
|------|------|-----------|------|
| `id` | UUID | 자동생성 | 고유 식별자 |
| `title` | string | ✅ 필수 | 할 일 제목 (최대 100자) |
| `description` | string | 선택 | 상세 설명 (최대 500자) |
| `priority` | enum | ✅ 필수 | `high` / `medium` / `low` (기본값: `medium`) |
| `dueDate` | date \| null | 선택 | 마감일 |
| `completed` | boolean | 자동 | 완료 여부 (기본값: `false`) |
| `createdAt` | timestamp | 자동생성 | 생성 시각 |
| `updatedAt` | timestamp | 자동생성 | 최종 수정 시각 |

### 2.3 필터링 & 정렬

| 기능 | 설명 | 우선순위 |
|------|------|----------|
| 상태 필터 | 전체 / 진행중 / 완료 탭 전환 | P0 |
| 우선순위 필터 | 높음 / 보통 / 낮음 필터링 | P1 |
| 마감일 정렬 | 마감일 임박순 / 생성일순 정렬 | P1 |
| 검색 | 제목 기반 키워드 검색 | P1 |

### 2.4 부가 기능

| 기능 | 설명 | 우선순위 |
|------|------|----------|
| 마감일 시각 표시 | 마감 임박(D-day) 항목 시각적 강조 | P1 |
| 완료 항목 일괄 삭제 | 완료된 투두 한 번에 정리 | P1 |
| 투두 카운터 | 전체/진행중/완료 개수 표시 | P2 |
| 다크모드 | 라이트/다크 테마 전환 | P2 |

## 3. 사용자 스토리

### US-01: 할 일 추가
> **사용자로서**, 새로운 할 일을 빠르게 입력하고 추가할 수 있다.
> **그래서** 떠오르는 태스크를 즉시 기록하여 잊지 않을 수 있다.

**인수 조건 (Acceptance Criteria):**
- 제목 입력 후 Enter 키 또는 추가 버튼으로 투두 생성
- 제목이 비어있으면 추가 버튼 비활성화 및 유효성 안내 표시
- 생성 시 우선순위 기본값은 `medium`, 완료 상태는 `false`
- 추가 후 입력 필드 자동 초기화 및 포커스 유지

### US-02: 할 일 완료 처리
> **사용자로서**, 완료한 할 일을 체크하여 완료 상태로 변경할 수 있다.
> **그래서** 진행 중인 일과 끝난 일을 명확히 구분할 수 있다.

**인수 조건:**
- 체크박스 클릭으로 완료/미완료 토글
- 완료된 항목은 취소선 스타일 적용 및 시각적 구분
- 완료 상태 변경 시 즉시 localStorage에 반영

### US-03: 우선순위 설정
> **사용자로서**, 각 할 일에 우선순위(높음/보통/낮음)를 지정할 수 있다.
> **그래서** 중요한 일을 먼저 파악하고 처리 순서를 결정할 수 있다.

**인수 조건:**
- 투두 생성 시 또는 수정 시 우선순위 선택 가능
- 우선순위별 색상 뱃지 표시 (높음: 빨강, 보통: 노랑, 낮음: 파랑)
- 우선순위 기준 필터링 가능

### US-04: 마감일 기반 관리
> **사용자로서**, 할 일에 마감일을 설정하고 임박한 항목을 한눈에 확인할 수 있다.
> **그래서** 기한 내에 태스크를 완료하도록 관리할 수 있다.

**인수 조건:**
- 날짜 선택기(date picker)로 마감일 설정/변경
- 마감일 지난 미완료 항목은 빨간색 경고 스타일 표시
- 마감일 임박순 정렬 옵션 제공
- 마감일 없는 항목은 정렬 시 하단 배치

### US-05: 필터링으로 목록 탐색
> **사용자로서**, 상태(전체/진행중/완료)별로 투두 목록을 필터링할 수 있다.
> **그래서** 현재 집중해야 할 항목만 빠르게 확인할 수 있다.

**인수 조건:**
- 전체 / 진행중 / 완료 3개 탭 제공
- 활성 탭 시각적 강조 표시
- 필터 전환 시 즉시 목록 갱신 (깜빡임 없음)
- 각 탭에 해당 항목 개수 표시

### US-06: 할 일 삭제
> **사용자로서**, 불필요한 할 일을 개별 삭제하거나 완료 항목을 일괄 삭제할 수 있다.
> **그래서** 목록을 깔끔하게 유지할 수 있다.

**인수 조건:**
- 개별 삭제 버튼 클릭 시 확인 없이 즉시 삭제 (Undo 가능하면 P2)
- "완료 항목 모두 삭제" 버튼 제공
- 일괄 삭제 시 확인 다이얼로그 표시
- 삭제 후 목록 즉시 갱신

### US-07: 할 일 검색
> **사용자로서**, 키워드로 할 일을 검색할 수 있다.
> **그래서** 많은 항목 중에서 원하는 태스크를 빠르게 찾을 수 있다.

**인수 조건:**
- 검색 입력 시 실시간(debounce 300ms) 필터링
- 제목 기준 부분 일치 검색
- 검색 결과 없을 시 "검색 결과가 없습니다" 안내 표시
- 검색어 초기화(X) 버튼 제공

## 4. 기술 요구사항

### 4.1 프론트엔드

| 항목 | 기술 선택 | 근거 |
|------|-----------|------|
| **프레임워크** | React 18+ | 컴포넌트 기반 UI, 풍부한 생태계 |
| **언어** | TypeScript | 타입 안전성, 개발 생산성 향상 |
| **빌드 도구** | Vite | 빠른 HMR, 경량 번들링 |
| **스타일링** | CSS Modules 또는 Tailwind CSS | 스코프 격리, 유틸리티 기반 빠른 스타일링 |

### 4.2 상태 관리

| 항목 | 기술 선택 | 근거 |
|------|-----------|------|
| **전역 상태** | Zustand | 경량, 보일러플레이트 최소, React 친화적 |
| **대안** | useContext + useReducer | 외부 의존성 없이 React 내장 기능 활용 (MVP 대안) |

**상태 구조 설계:**
```typescript
interface TodoState {
  todos: Todo[];
  filter: 'all' | 'active' | 'completed';
  searchQuery: string;
  sortBy: 'createdAt' | 'dueDate' | 'priority';

  // Actions
  addTodo: (todo: Omit<Todo, 'id' | 'createdAt' | 'updatedAt'>) => void;
  updateTodo: (id: string, updates: Partial<Todo>) => void;
  deleteTodo: (id: string) => void;
  toggleTodo: (id: string) => void;
  clearCompleted: () => void;
  setFilter: (filter: TodoState['filter']) => void;
  setSearchQuery: (query: string) => void;
  setSortBy: (sortBy: TodoState['sortBy']) => void;
}
```

### 4.3 데이터 영속성 (스토리지)

| 항목 | 기술 선택 | 근거 |
|------|-----------|------|
| **저장소** | localStorage | 서버 불필요, 즉시 사용 가능, MVP 적합 |
| **직렬화** | JSON.stringify / JSON.parse | 표준 직렬화 |
| **동기화** | Zustand persist middleware | 상태 변경 시 자동 localStorage 동기화 |

**스토리지 전략:**
- 키: `todo-app-state`
- 상태 변경 시 자동 저장 (persist middleware)
- 앱 로드 시 localStorage에서 자동 복원
- 저장 용량 제한 고려: 최대 5MB (localStorage 제한)

## 6. 비기능 요구사항

### 6.1 성능

| 항목 | 목표 | 측정 방법 |
|------|------|-----------|
| **초기 로딩** | FCP ≤ 1.5초 | Lighthouse |
| **인터랙션 응답** | 모든 UI 조작 100ms 이내 반응 | 체감 측정 |
| **번들 사이즈** | JS 번들 ≤ 200KB (gzip) | Vite build 분석 |
| **렌더링** | 투두 100개 기준 스크롤 60fps 유지 | Chrome DevTools |
| **검색 디바운스** | 입력 후 300ms 대기 후 필터링 실행 | 구현 로직 |

**성능 최적화 전략:**
- `React.memo`로 불필요한 리렌더링 방지
- 투두 목록 가상화 (100개 초과 시 `react-window` 도입 검토)
- 검색 입력 debounce 처리
- 코드 스플리팅 최소화 (SPA 단일 페이지)

### 6.2 접근성 (a11y)

| 항목 | 요구사항 | 기준 |
|------|----------|------|
| **WCAG 준수** | WCAG 2.1 AA 레벨 | 국제 표준 |
| **키보드 내비게이션** | 모든 기능 키보드만으로 조작 가능 | Tab, Enter, Escape, Space |
| **스크린 리더** | 시맨틱 HTML + ARIA 레이블 적용 | NVDA/VoiceOver 테스트 |
| **색상 대비** | 텍스트/배경 대비율 4.5:1 이상 | Contrast Checker |
| **포커스 표시** | 포커스 상태 시각적으로 명확히 표시 | outline 스타일 |
| **폼 레이블** | 모든 입력 필드에 연결된 label 제공 | `<label htmlFor>` |

**접근성 구현 상세:**
```
- 체크박스: role="checkbox", aria-checked 상태 관리
- 필터 탭: role="tablist" / role="tab" / aria-selected
- 삭제 버튼: aria-label="[투두 제목] 삭제"
- 우선순위 뱃지: aria-label="우선순위: 높음"
- 마감일 경고: role="alert" (마감 초과 시)
- 빈 목록: aria-live="polite"로 상태 안내
```
