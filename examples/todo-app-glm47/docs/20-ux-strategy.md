## 1. 전략 개요 (Strategy Overview)

### 1.1 UX 비전 (UX Vision)

| 항목 | 내용 |
|------|------|
| **비전 선언** | "즉시 실행 가능한 직관적 태스크 관리 경험" |
| **핵심 가치** | 속도, 단순함, 명확성, 접근성 |
| **타겟 사용자** | 일상 태스크 관리가 필요한 일반 사용자, 키보드/스크린 리더 사용자 포함 |

### 1.2 UX 원칙 (UX Principles)

| 원칙 | 설명 | 적용 예시 |
|------|------|----------|
| **Speed First** | 최소 클릭/키 입력으로 태스크 추가 | 엔터키로 즉시 추가 |
| **Immediate Feedback** | 모든 액션에 즉각적 시각 피드백 | 토글/삭제 시 즉시 반영 |
| **Visual Clarity** | 상태를 시각적으로 명확히 구분 | 완료/미완료 명확 구분 |
| **Progressive Disclosure** | 불필요한 정보 숨김 | 필터링으로 집중된 목록 |
| **Forgiveness** | 실수를 쉽게 복구 가능 | 삭제 후에도 재생성 용이 |
| **Accessibility First** | WCAG 2.1 AA 준수, 모든 사용자 접근 가능 | 키보드 전체 지원, 색상 대비비 준수 |

### 1.3 성공 지표 (Success Metrics)

| 지표 | 목표값 | 측정 방법 |
|------|--------|----------|
| 태스크 추가 시간 | < 2초 | 입력 → 저장 완료 시간 |
| 태스크 완료 토글 | < 0.5초 | 클릭 → 상태 변경 시간 |
| 새 사용자 학습 시간 | < 1분 | 첫 사용부터 첫 완료까지 |
| 오류 발생률 | < 1% | 사용자 오류 액션 비율 |
| WCAG 2.1 AA 준수율 | 100% | 모든 대비비/터치 타겟/키보드 기능 준수 |

### 2.2 핵심 시나리오 여정 (Core Scenario Journey)

#### 시나리오 1: 첫 방문 및 첫 태스크 추가

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  앱 접속     │ →   │  빈 목록    │ →   │  태스크 입력 │ →   │  태스크 추가 │
│  (로딩)     │     │  안내 확인  │     │  (텍스트)   │     │  (완료)     │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
      │                   │                   │                   │
      ▼                   ▼                   ▼                   ▼
   페이지           "No tasks           입력 필드            목록에 표시,
   로드 완료        found"              자동 포커스           저장 완료
                                           (visible label)
```

**UX 고려사항:**
- 입력 필드에 자동 포커스
- 빈 상태 명확한 안내 메시지
- 엔터키로 즉시 추가
- localStorage 자동 저장 (사용자 인지 불필요)
- **접근성:** `<label for="input">What needs to be done?</label>` visible label 제공

#### 시나리오 2: 태스크 완료 및 필터링

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  전체 목록   │ →   │  완료 토글  │ →   │  필터 전환  │ →   │  완료 목록   │
│  (여러 개)  │     │  (체크박스) │     │  (버튼)     │     │  (완료만)   │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
      │                   │                   │                   │
      ▼                   ▼                   ▼                   ▼
   All/Active/     즉시 시각적            Active 버튼          완료된
   Completed       피드백 (취소선)          비활성화            항목만 표시
   (포커스 유지)
```

**UX 고려사항:**
- 토글 시 즉시 시각적 피드백 (취소선, 색상 변경)
- 현재 필터 버튼 명확한 활성 상태 표시
- 빈 필터 결과 시 적절한 메시지
- **접근성:** 필터링 결과 없음 시 포커스가 FilterBar에 유지되어 다음 동작 가능

#### 시나리오 3: 태스크 삭제

```
┌─────────────┐     ┌─────────────────────┐     ┌─────────────┐
│  태스크 선택 │ →   │  삭제 버튼 클릭     │ →   │  확인 다이얼로그│
│  (대상 식별)│     │  (Enter/Space)      │     │  (확인/취소)  │
└─────────────┘     └─────────────────────┘     └─────────────┘
      │                   │                           │
      ▼                   ▼                           ▼
   항목 hover       삭제 확인 대화상장           [확인] → 목록에서 제거
   (마우스 사용)     [취소] → 아무 일 없음         [취소] → 원래 상태
                     포커스 트랩 적용
```

**UX 고려사항:**
- **삭제 확인 다이얼로그 추가** (A11Y-P1-006 수정)
- 삭제 애니메이션 (fade-out)으로 부드러운 전환
- 삭제 후 포커스 적절한 위치로 이동
- **접근성:** 모달 열린 시 포커스 트랩(focus trap) 적용, 닫힌 시 포커스 복귀

#### 시나리오 4: 다중 탭 사용

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  탭 A 사용  │ →   │  태스크 추가 │ →   │  탭 B 확인  │
│  (기존)    │     │  (A에서)    │     │  (동기화)   │
└─────────────┘     └─────────────┘     └─────────────┘
      │                   │                   │
      ▼                   ▼                   ▼
   기존 상태        localStorage에         storage 이벤트로
   로드            저장됨                 자동 동기화
                                          (스크린 리더 알림)
```

**UX 고려사항:**
- 사용자 조작 없는 자동 동기화
- 동기화 시점의 시각적 피드백 (선택적)

## 3. 정보 아키텍처 (Information Architecture)

### 3.1 IA 구조도 (IA Structure)

```
TODO App
│
├── TodoApp (Root)
│   │
│   ├── AddTodo (입력 영역)
│   │   ├── <form> (HTML 시맨틱)
│   │   │   ├── <label for="todo-input"> (visible label)
│   │   │   ├── <input id="todo-input">
│   │   │   └── <button> 추가 버튼
│   │   └── role="group" aria-label="Add new task"
│   │
│   ├── DeleteConfirmDialog (삭제 확인 다이얼로그)
│   │   ├── role="dialog"
│   │   ├── aria-modal="true"
│   │   ├── aria-labelledby="dialog-title"
│   │   └── focus trap 적용
│   │
│   ├── TodoList (목록 영역)
│   │   ├── <ul> role="list"
│   │   ├── Empty State (빈 상태)
│   │   │   └── "No tasks found" 메시지
│   │   │
│   │   └── TodoItem[] (동적 항목)
│   │       ├── <li> role="listitem"
│   │       │   ├── 토글 버튼 (완료/미완료)
│   │       │   ├── 텍스트 내용
│   │       │   └── 삭제 버튼
│   │       └── role="group" aria-label="Task: {text}"
│   │
│   └── FilterBar (필터 영역)
│       ├── <nav role="navigation"> (HTML 시맨틱)
│       ├── All 버튼
│       ├── Active 버튼
│       └── Completed 버튼
```

### 3.2 콘텐츠 계층 (Content Hierarchy)

| 계층 | 요소 | 설명 | 시각적 강조 |
|------|------|------|-------------|
| L0 (최상위) | TodoApp | 전체 컨테이너 | 중립 |
| L1 | AddTodo | 태스크 추가 영역 | 높은 강조 (입력 유도) |
| L1 | DeleteConfirmDialog | 삭제 확인 다이얼로그 | 최고 강조 (중요) |
| L1 | TodoList | 태스크 목록 영역 | 중간 강조 |
| L2 | TodoItem | 개별 태스크 | 중간 강조 |
| L2 | FilterBar | 필터 버튼 그룹 | 낮은 강조 (보조 기능) |
| L3 | Empty State | 빈 상태 메시지 | 낮은 강조 |

### 3.4 네비게이션 모델 (Navigation Model)

| 네비게이션 유형 | 설명 | 패턴 |
|-----------------|------|------|
| **선형 네비게이션** | 태스크 목록 순차 탐색 | Tab 키로 순차 이동 |
| **필터 기반 네비게이션** | All → Active → Completed | 버튼 클릭으로 전환 |
| **컨텍스트 네비게이션** | 항목 내 작업 (토글/삭제) | 해당 항목 내에서 처리 |
| **모달 네비게이션** | 삭제 확인 다이얼로그 | 포커스 트랩, Escape 닫기 |

### 3.5 레이블링 표준 (Labeling Standards)

| 요소 | 레이블 | ARIA 레이블 | 설명 |
|------|--------|-------------|------|
| 입력 필드 | `<label for="todo-input">What needs to be done?</label>` | (제거 - visible label 사용) | 새 태스크 입력 (visible label 필수) |
| 추가 버튼 | "+" | aria-label="Add task" | 태스크 추가 |
| 토글 버튼 | (아이콘) | aria-label="Toggle todo: {task text}" / aria-pressed | 완료 상태 변경 |
| 삭제 버튼 | × | aria-label="Delete task: {task text}" | 태스크 삭제 |
| All 필터 | "All" | aria-label="Show all tasks" | 전체 태스크 |
| Active 필터 | "Active" | aria-label="Show active tasks" | 미완료 태스크 |
| Completed 필터 | "Completed" | aria-label="Show completed tasks" | 완료된 태스크 |
| 빈 상태 | "No tasks found" | role="status" | 태스크 없음 |
| DeleteConfirmDialog | "Delete task?" | role="dialog", aria-modal="true", aria-labelledby="dialog-title" | 삭제 확인 |

## 4. TODO 도메인 제약사항 (TODO Domain Constraints)

### 4.1 도메인 범위 제약 (Domain Scope Constraints)

| 제약 항목 | 설명 | 영향 범위 |
|-----------|------|-----------|
| **단순 TODO만** | 서브태스크, 마감일, 태그, 우선순위 미지원 | 데이터 모델, UI |
| **텍스트만** | 첨부 파일, 이미지, 링크 미지원 | TodoItem 구조 |
| **3가지 필터** | All, Active, Completed만 지원 | FilterBar 구조 |
| **로컬 전용** | 서버 동기화, 공유 기능 미지원 | 저장 전략 |

### 4.2 데이터 제약 (Data Constraints)

| 제약 | 값 | UX 영향 |
|------|-----|----------|
| 태스크 텍스트 길이 | 1-200자 | 입력 필드 validation 메시지, 문자 수 표시 |
| 태스크 개수 제한 | 1000개 권장 | 초과 시 경고 메시지 |
| 필터 유형 | 3가지 고정 | 필터 UI 고정 |
| 고유 ID | 타임스탬프 + 랜덤 | 사용자 노출 불필요 |

### 4.3 기술 제약 (Technical Constraints)

| 제약 | 설명 | UX 영향 |
|------|------|----------|
| 순수 JavaScript | 프레임워크/라이브러리 비사용 | 직접 DOM 조작 |
| localStorage 저장 | 5MB 제한 | 대량 데이터 시 경고 |
| 최신 브라우저 | 2개 버전만 지원 | 레거시 브라우저 미지원 |
| CustomEvent 이벤트 | 컴포넌트 간 통신 | 상태 변경 즉시 반영 |
| focus-visible 폴리필 | Safari < 15.4 지원 | 포커스 인디케이터 호환성 확보 |

### 4.4 접근성 제약 (Accessibility Constraints)

| 제약 | 설명 | UX 영향 |
|------|------|----------|
| WCAG 2.1 AA 준수 | 모든 대비비/터치 타겟/키보드 기능 준수 | 색상, 크기, 키보드 스펙 |
| 키보드 전체 기능 | 모든 기능 키보드 접근 가능 | Tab 인덱스, Space/Enter 지원 |
| 색상 대비비 | WCAG AA 4.5:1 준수 (텍스트), AAA 7:1 권장 | 컬러 팔레트 제약 |
| 스크린 리더 | 모든 상태 읽기 가능 | ARIA 속성, 시맨틱 HTML 필수 |
| 포커스 관리 | 삭제 후 포커스 이동, 포커스 트랩 | 포커스 로직 명시 |
| 터치 타겟 | 최소 44x44px (WCAG 2.5.5) | 버튼, 토글, 삭제 버튼 크기 |
| HTML 시맨틱 | 적절한 태그 사용 (`<form>`, `<nav>`, `<ul>`) | 검토 및 수정 필요 |

### 4.5 UI 제약 (UI Constraints)

| 제약 | 설명 | UX 영향 |
|------|------|----------|
| 단일 페이지 | 페이지 이동 없음 | 모든 상태 한 화면에 표시 |
| BEM 명명 규칙 | CSS 클래스 명명 | 클래스 이름 구조 |
| Flexbox 레이아웃 | 유연한 레이아웃 | 반응형 디자인 |
| 하드웨어 가속 | transform 사용 | 애니메이션 성능 |
| 색상 대비비 | Error/Warning 대비비 4.5:1 이상 | CSS 변수 수정 |

### 4.6 인터랙션 제약 (Interaction Constraints)

| 제약 | 설명 | UX 영향 |
|------|------|----------|
| 삭제 확인 있음 | 다이얼로그로 확인 후 삭제 | 안전성 확보 (A11Y-P1-006 수정) |
| 드래그 앤 드롭 미지원 | 순서 변경 불가 | 생성 순서 고정 |
| 일괄 작업 미지원 | 개별 작업만 | 하나씩 토글/삭제 |
| Space 키 표준 준수 | 체크박스 토글은 Space만 (A11Y-P2-003 수정) | 키보드 호환성 |

### 5.1 입력 패턴 (Input Patterns)

| 패턴 | 적용 | 설명 |
|------|------|------|
| **Inline Input** | AddTodo | 별도 페이지 없이 입력 필드로 즉시 입력 |

### 5.2 상태 패턴 (State Patterns)

| 패턴 | 적용 | 설명 |
|------|------|------|

| **Focus Indicator** | 키보드 탐색 | 포커스 시 명확한 테두리 |

| **Delete Confirmation** | 삭제 시 | 다이얼로그로 확인 요청 |

## 6. 반응형 전략 (Responsive Strategy)

### 6.1 뷰포트 정의 (Viewport Definitions)

| 뷰포트 | 범위 | 레이아웃 전략 |
|--------|------|--------------|
| **Mobile** | < 768px | 단열 레이아웃, 최소 여백 |
