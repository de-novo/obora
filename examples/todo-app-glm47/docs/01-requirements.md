# TODO 앱 요구사항 정의서

## 페르소나

- **이수진 (28세, 소프트웨어 엔지니어)**
  - 일일 업무 태스크를 체계적으로 관리하고자 함
  - 간단하고 빠르게 태스크를 추가/완료/삭제하기를 원함
  - 브라우저 종료 후에도 데이터가 유지되기를 기대함

## 목표

- 사용자가 태스크를 추가, 조회, 완료, 삭제할 수 있는 웹 앱 제공
- 필터링을 통해 상태별(전체/진행중/완료) 태스크를 빠르게 확인
- localStorage를 통해 데이터 영속성 보장
- 직관적이고 반응형 UI 제공

## 기능 요구사항

### MUST (필수)

| 기능 | 설명 |
|------|------|
| Todo CRUD | 태스크 생성, 목록 조회, 수정(완료 토글), 삭제 |
| 완료 토글 | 태스크의 완료 상태를 ON/OFF 전환 |
| 삭제 | 개별 태스크 삭제 |
| 필터 | 전체(All) / 진행중(Active) / 완료(Completed) 필터링 |
| localStorage | 브라우저 새로고침 후에도 데이터 유지 |

### SHOULD (권장)

| 기능 | 설명 |
|------|------|
| 입력 유효성 검증 | 빈 문자열 입력 방지, trim 처리 |
| 완료 상태 시각화 | 완료된 태스크에 취소선/회색 처리 |
| 필터 상태 유지 | 페이지 새로고침 시 마지막 필터 상태 복원 |

### COULD (선택)

| 기능 | 설명 |
|------|------|
| 다크 모드 | 사용자 테마 선택 지원 |
| 태스크 개수 카운터 | 각 필터별 남은 태스크 수 표시 |

## 제약사항

- **기술 스택**: 순수 JavaScript + CSS + HTML (프레임워크 비사용)
- **데이터 저장**: 브라우저 localStorage만 사용 (서버 API 없음)
- **브라우저 호환성**: 최신 브라우저(Chrome, Firefox, Safari, Edge) 최신 2개 버전
- **디바이스**: 데스크톱 및 태블릿 지원 (모바일 반응형 권장)
- **접근성**: 키보드 탐색 가능, ARIA 속성 사용

## KPI

| 지표 | 목표 | 측정 방법 |
|------|------|----------|
| 기능 완료율 | MUST 항목 100% 구현 | 기능 체크리스트 검증 |
| 로드 시간 | 500ms 이하 | 브라우저 DevTools Network 탭 |
| 데이터 유지율 | localStorage 저장/복구 100% | 새로고침 후 데이터 일치 확인 |
| UI 반응 속도 | 사용자 액션 후 100ms 이내 반응 | 수동 테스트 |

## MVP 범위

- **TodoApp**: 메인 컴포넌트, 상태 관리 중심
- **TodoList**: 태스크 목록 렌더링
- **TodoItem**: 개별 태스크 행 (완료 토글, 삭제 버튼)
- **AddTodo**: 새 태스크 입력 폼
- **FilterBar**: 필터 버튼 그룹 (All/Active/Completed)
