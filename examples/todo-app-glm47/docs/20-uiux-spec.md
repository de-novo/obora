## 1. 개요

본 문서는 TODO 앱의 정보 아키텍처(IA), 사용자 흐름, 화면 상태, 접근성 요구사항을 정의합니다. 아키텍처 설계서(docs/10-architecture.md)의 컴포넌트 구조와 데이터 모델을 기반으로 사용자 경험을 설계합니다.

### 1.1 설계 원칙

| 원칙 | 설명 |
|------|------|
| 명확성 | 사용자의 의도를 직관적으로 파악할 수 있는 인터페이스 |
| 효율성 | 최소한의 조작으로 원하는 작업 완료 |
| 접근성 | 모든 사용자가 동등한 경험 제공 |
| 일관성 | 아키텍처의 단방향 데이터 흐름과 UI 상태 일치 |

## 2. 정보 아키텍처 (IA)

### 2.1 사이트맵

```
TODO 앱 (단일 페이지)
├── 태스크 입력 영역 (AddTodo)
│   ├── 텍스트 입력 필드
│   └── 추가 버튼
├── 필터 영역 (FilterBar)
│   ├── 전체 (All)
│   ├── 진행중 (Active)
│   └── 완료 (Completed)
└── 태스크 목록 영역 (TodoList)
    └── 태스크 아이템들 (TodoItem[])
        ├── 완료 체크박스
        ├── 태스크 텍스트
        └── 삭제 버튼
```

### 2.2 정보 계층 구조

| 레벨 | 영역 | 우선순위 | 설명 |
|------|------|----------|------|
| L1 | 태스크 입력 | 높음 | 사용자의 첫 번째 목표 |
| L1 | 태스크 목록 | 높음 | 현재 상태 파악 |
| L2 | 필터링 | 중간 | 대량 태스크 관리 |
| L3 | 태스크 삭제 | 낮음 | 빈도가 낮음 |

### 2.3 컨텐츠 모델

| 엔티티 | 속성 | 표현 |
|--------|------|------|
| 태스크 | id, text, completed | TodoItem으로 시각화 |
| 필터 | all, active, completed | FilterBar 버튼으로 시각화 |
| 상태 | todos[], filter | 화면 레이아웃으로 반영 |

## 3. 사용자 흐름 (User Flow)

### 3.1 전체 사용자 흐름 다이어그램

```
┌─────────────┐
│ 앱 진입     │
└──────┬──────┘
       │
       ▼
┌─────────────────────────────────────┐
│ 기존 태스크 로드 (localStorage)    │
│ 필터 상태 복원                      │
└──────┬──────────────────────────────┘
       │
       ▼
┌─────────────────────────────────────┐
│ 메인 화면 렌더링                    │
│ - AddTodo 활성화                     │
│ - TodoList 표시                     │
│ - FilterBar 상태 표시               │
└─────────────────────────────────────┘
       │
       ├─────────────────────┬─────────────────────┐
       ▼                     ▼                     ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 태스크 추가  │    │ 태스크 토글  │    │ 태스크 삭제  │
└──────┬───────┘    └──────┬───────┘    └──────┬───────┘
       │                   │                   │
       ▼                   ▼                   ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 입력 → 버튼  │    │ 체크박스 클릭│    │ 삭제 버튼    │
└──────┬───────┘    └──────┬───────┘    └──────┬───────┘
       │                   │                   │
       └───────────────────┼───────────────────┘
                           │
                           ▼
                  ┌────────────────┐
                  │ 상태 업데이트  │
                  │ localStorage   │
                  │ 저장           │
                  └────────┬───────┘
                           │
                           ▼
                  ┌────────────────┐
                  │ 화면 재렌더링  │
                  └────────────────┘
```

### 3.2 태스크 추가 흐름

| 단계 | 사용자 동작 | 시스템 응답 | 상태 변화 |
|------|-----------|-----------|----------|
| 1 | 입력 필드에 텍스트 입력 | 입력값 표시 | Input value 업데이트 |
| 2 | Enter 키 또는 추가 버튼 클릭 | 입력 필드 초기화, 태스크 추가 | `todos.push()`, filter 유지 |
| 3 | (애니메이션) | 새 태스크 fade-in | - |
| 4 | (백그라운드) | localStorage 저장 (100ms debounce) | 데이터 영속화 |

### 3.3 태스크 완료 토글 흐름

| 단계 | 사용자 동작 | 시스템 응답 | 상태 변화 |
|------|-----------|-----------|----------|
| 1 | 체크박스 클릭 | 체크박스 상태 변경 | `completed = !completed` |
| 2 | (시각) | 텍스트 취소선 적용/해제 | - |
| 3 | (필터 상태에 따라) | 목록에서 제거 또는 유지 | `filter`에 따라 렌더링 |
| 4 | (백그라운드) | localStorage 저장 | 데이터 영속화 |

### 3.4 태스크 삭제 흐름

| 단계 | 사용자 동작 | 시스템 응답 | 상태 변화 |
|------|-----------|-----------|----------|
| 1 | 삭제 버튼 클릭 | 태스크 fade-out 애니메이션 | - |
| 2 | (애니메이션 완료 후) | DOM에서 제거 | `todos.filter()` |
| 3 | (백그라운드) | localStorage 저장 | 데이터 영속화 |

### 3.5 필터링 흐름

| 단계 | 사용자 동작 | 시스템 응답 | 상태 변화 |
|------|-----------|-----------|----------|
| 1 | 필터 버튼 클릭 (All/Active/Completed) | 활성 버튼 스타일 변경 | `filter` 업데이트 |
| 2 | 목록 필터링 적용 | 해당 상태의 태스크만 표시 | 렌더링 필터 적용 |
| 3 | (빈 상태인 경우) | "태스크가 없습니다" 메시지 | - |
| 4 | (백그라운드) | 필터 상태 저장 | filter 영속화 |

## 4. 화면 상태 (Screen States)

### 4.1 상태 유형

| 상태 유형 | 설명 | 트리거 조건 |
|----------|------|-----------|
| 초기 상태 | 앱 첫 로딩 | localStorage 데이터 없음 |
| 데이터 있음 | 태스크 존재 | `todos.length > 0` |
| 데이터 없음 (빈 상태) | 태스크 없음 | `todos.length === 0` |
| 필터링 상태 | 특정 필터 선택 | `filter !== 'all'` |
| 오류 상태 | localStorage 실패 | QuotaExceededError 등 |
| 로딩 상태 | 데이터 로딩 중 | 앱 초기화 (50ms 이내) |

### 4.3 컴포넌트별 상태

#### 4.3.1 AddTodo 상태

| 상태 | 설명 | UI 표현 |
|------|------|---------|
| idle | 입력 대기 | 빈 입력 필드, 플레이스홀더 표시 |
| typing | 입력 중 | 텍스트 표시 |
| validating | 유효성 검증 중 | (미표시, 즉시 처리) |
| error | 유효성 오류 | 빈 입력 시 경고 텍스트 |

#### 4.3.2 FilterBar 상태

| 상태 | 필터 | UI 표현 |
|------|------|---------|
| all | 'all' | 전체 버튼 활성 스타일 |
| active | 'active' | 진행중 버튼 활성 스타일 |
| completed | 'completed' | 완료 버튼 활성 스타일 |

#### 4.3.3 TodoList 상태

| 상태 | 조건 | UI 표현 |
|------|------|---------|
| has-items | `filteredTodos.length > 0` | TodoItem 목록 표시 |
| empty | `filteredTodos.length === 0` | 빈 상태 메시지 표시 |
| empty-all | `todos.length === 0` | "첫 태스크를 추가하세요" |
| empty-filtered | `todos.length > 0 && filteredTodos.length === 0` | "해당 상태의 태스크가 없습니다" |

#### 4.3.4 TodoItem 상태

| 상태 | completed | UI 표현 |
|------|-----------|---------|
| active | false | 체크박스 unchecked, 일반 텍스트 |
| completed | true | 체크박스 checked, 취소선 텍스트, 연한 색상 |

## 5. 접근성 (Accessibility)

| 태스크 추가 버튼 | "태스크 추가, 버튼" |
| 완료된 태스크 | "태스크 내용, 완료됨, 체크박스, 체크됨" |

| 태스크 삭제 | "태스크 내용 삭제, 버튼" |

### 5.7 동적 콘텐츠 접근성

| 상황 | 접근성 처리 |

## 7. 애니메이션 및 트랜지션

### 7.1 애니메이션 원칙

| 원칙 | 설명 |
|------|------|
| 사용자 제어 | `prefers-reduced-motion` 존중 |
| 성능 | transform/opacity 사용, layout 변경 최소화 |
| 목적성 | 사용자 피드백 제공 |
| 지속시간 | 200-300ms (기본), 500ms (최대) |

### 7.2 애니메이션 명세

| 액션 | 속성 | 지속시간 | 이징 함수 |
|------|------|----------|-----------|
| 태스크 추가 | opacity, transform (translateY) | 250ms | ease-out |
| 태스크 삭제 | opacity, transform (translateX) | 200ms | ease-in |
| 완료 토글 | opacity, color | 200ms | ease-in-out |
| 필터 변경 | opacity | 150ms | ease-in-out |
| 버튼 hover | background-color | 150ms | ease-in-out |

### 7.3 리듀스 모션 지원

```css
@media (prefers-reduced-motion: reduce) {
  * {
    animation-duration: 0.01ms !important;
    transition-duration: 0.01ms !important;
  }
}
```

## 13. 검증 체크리스트

### 13.1 기능 검증

- [ ] 태스크 추가가 정상적으로 작동하는가
- [ ] 태스크 완료 토글이 시각적으로 반영되는가
- [ ] 태스크 삭제가 애니메이션과 함께 작동하는가
- [ ] 세 가지 필터가 모두 올바르게 작동하는가
- [ ] 빈 상태 메시지가 적절한 상황에 표시되는가

### 13.2 접근성 검증

- [ ] 키보드로 모든 기능을 조작할 수 있는가
- [ ] 포커스 가시성이 충분한가
- [ ] 스크린 리더가 모든 상태를 올바르게 읽는가
- [ ] 색상 대비비가 WCAG AA를 충족하는가
- [ ] 터치 타겟이 최소 44×44px 이상인가

### 13.3 UX 검증

- [ ] 사용자 흐름이 직관적인가
- [ ] 피드백이 적시에 제공되는가
- [ ] 에러 메시지가 명확한가
- [ ] 애니메이션이 자연스러운가
- [ ] 반응형 레이아웃이 모든 브레이크포인트에서 작동하는가
