# 문제 프레임

## 연구 목적
Obora의 검증-수정 루프(Validation-Repair Loop) 메커니즘의 구조와 동작 원리를 분석하여, AI 기반 시스템에서 안정적인 실행 보장 방법을 규명한다.

## 핵심 문제정의
AI의 비결정적 출력 특성으로 인한 시스템 안정성 저하 문제를 해결하기 위해, 검증 실패 시 자동 수정과 재검증을 반복하는 구조적 루프가 어떻게 작동하고 안정성을 보장하는지 파악해야 한다.

## 연구 질문

1. **구조적 질문**: Obora의 Validation-Repair Loop는 어떤 구성요소(Step, on_fail, repair_loop 설정)로 조합되며, 각 구성요소의 의존관계와 실행 흐름은 어떻게 정의되는가?

2. **기능적 질문**: 검증 단계에서 실패가 발생했을 때, 시스템은 어떤 조건에서 수정 단계로 이동하고, 최대 반복 횟수 및 진행 상태(진전 여부)를 어떻게 추적하여 종료 조건을 결정하는가?

3. **효과 질문**: Validation-Repair Loop가 적용된 워크플로우가 적용되지 않은 워크플로우 대비 안정성 향상(실패 복구율, 수렴 성공률)을 정량적으로 어떻게 측정할 수 있는가?

## 범위 / 비범위

### 포함 (범위)
- Obora 런타임의 Validation-Repair Loop 설정 구조
- `repair_loop`, `toolLimits`, `on_fail`, `max_iterations` 설정의 동작 원리
- 검증 실패 시 복구 흐름과 상태 추적 메커니즘
- `.sandbox/12-reddit-clone-modern-repair-loop` 예제 분석

### 제외 (비범위)
- 특정 LLM 제공자(OpenAI, ZAI 등)의 API 동작 세부사항
- 외부 검증 도구(스타일린터, 테스트 러너 등)의 구현
- 성능 최적화(지연 시간, 비용)에 대한 심층 분석
- 다중 에이전트 합의(Consensus) 메커니즘
