## Observation (관측 사항)

### O-001: 구조 관측
- **관측**: V-R Loop는 선형 파이프라인 위에 루프백 메커니즘이 중첩된 구조
- **세부사항**:
  - 기본 흐름: Step → Validation (성공 시 다음 Step)
  - 실패 흐름: Step → Validation (실패) → on_fail → repair_loop
- **특이사항**: 의존성은 방향성 그래프 형태로 정의되나, 루프백은 역방향 이동을 허용

### O-002: 상태 추적 관측
- **관측**: 시스템은 반복 상태를 명시적으로 추적함
- **추적 대상**:
  - iteration count (현재 반복 횟수)
  - no-progress counter (개선 없음 연속 횟수)
  - repeated issue counter (동일 이슈 반복 횟수)
- **카운터 초기화 규칙**: 증거에서 명시되지 않음 (가설 필요)

### O-003: 종료 조건 관측
- **관측**: 종료 조건은 두 계층으로 정의됨
  - **성공 종료**: 모든 필수 기준 만족
  - **안전 종료**: 실패 패턴 감지 시 bounded conclusion
- **결정 포인트**: 각 iteration의 review 단계에서 종료 여부 판단

### O-004: 실패 패턴 관측
- **관측**: 실패 신호는 "무시"와 "반복"으로 분류됨
  - 무시: 후속 문서가 선행 결정을 반영하지 않음
  - 반복: 동일 결함이 수정되지 않고 재발
- **근거 결핍**: 결론이 충분한 근거 없이 생성됨

### O-005: 컨텍스트 유지 관측
- **관측**: 연구 질문의 3차원 구조 유지가 필수 성공 기준
  - 구조 질문 (구성요소/의존관계)
  - 기능 질문 (조건/흐름/종료)
  - 효과 질문 (정량적 측정)
- **검증 포인트**: 중간 단계의 핵심 용어가 후속 문서에서 유지되는지

## Hypothesis (가설)

### H-001: 구조 가설
**가설**: V-R Loop의 구조는 계층적 상태 머신으로 모델링 가능하다.

- **예측**:
  - 각 Step은 상태(state)
  - on_fail은 전이 조건(guard condition)
  - repair_loop는 반복 상태 서브머신
- **검증 방법**: 상태 전이 다이어그램 작성 및 증거(E-004~E-006) 매핑

### H-002: 수렴 가설
**가설**: no-progress ceiling과 repeated issue ceiling은 수렴 보장을 위한 최소 충분 조건이다.

- **예측**:
  - ceiling=3과 ceiling=2 조합이 대부분의 실패 패턴을 탐지 가능
  - 그러나 일부 경계 조건(edge case)에서는 추가 조건 필요
- **검증 방법**: 실패 패턴 유형 분류 및 ceiling 값 민감도 분석

### H-003: 컨텍스트 붕괴 가설
**가설**: iteration 횟수가 증가할수록 컨텍스트 붕괴 위험이 기하급수적으로 증가한다.

- **예측**:
  - iteration 1-2: 컨텍스트 유지율 > 90%
  - iteration 3-4: 컨텍스트 유지율 60-80%
  - iteration 5+: 컨텍스트 유지율 < 50%
- **검증 방법**: iteration별 핵심 용어/판단 기준 유지율 측정

### H-004: 단일 모델 한계 가설
**가설**: GLM-4.7 단일 모델은 논문형 구조 유지에 충분하나, 심층적 검증(external validation)에는 불충분하다.

- **예측**:
  - 내부 정합성(internal consistency) 검증: 충분
  - 외부 타당성(external validity) 검증: 제한적
- **검증 방법**: 리뷰 결과의 P0/P1 이슈 유형 분석

### H-005: 추적성 향상 가설
**가설**: Obora의 명시적 아티팩트 정책은 단순 프롬프트 체인 대비 추적 가능성을 30% 이상 향상시킨다.

- **예측**:
  - 아티팩트 기반: 연구 흐름 재구성 가능
  - 프롬프트 체인: 중간 결정이 모델 내부에 흡수
- **검증 방법**: 제3자 재구성 테스트 및 완성도 평가

## Risk (위험 요소)

### R-001: 무한 루프 위험
- **위험**: 종료 조건의 불충분한 정의로 무한 반복 가능
- **발생 조건**:
  - P0 이슈가 계속 발생하되, 진전이 발생하지 않음
  - no-progress 카운터가 증가하나 종료 조건이 미달성
- **완화책**: 안전 중단 조건의 명시적 구현 (max_iterations=5)

### R-002: 의사 수렴(Pseudo-convergence) 위험
- **위험**: 겉보기에는 조건 충족하나, 실제 품질은 개선되지 않음
- **발생 조건**:
  - 용어는 유지되나 의미가 변형됨
  - 리뷰 결과가 formal하게 반영되나 실질 개신 없음
- **완화책**: 의미 수준의 검증(semanitc validation) 추가

### R-003: 컨텍스트 누적 위험
- **위험**: iteration이 반복될수록 선행 아티팩트의 충돌이 누적됨
- **발생 조건**:
  - remediation이 부분적 수정만 수행
  - 충돌하는 결정이 rollback되지 않음
- **완화책**: 결정 로그(decision log)의 충돌 감지 메커니즘

### R-004: 검증 기준 모호성 위험
- **위험**: P0/P1 이슈 분류 기준이 주관적일 수 있음
- **발생 조건**:
  - 단일 모델이 자가 검증 수행 시 편향 발생
  - 기준이 명시적이지 않아 결과가 모델 의존적
- **완화책**: 검증 기준의 정량화 및 예시 기반 정의

### R-005: 근거 연결 끊김 위험
- **위험**: 중간 결론과 최종 결론 사이의 인과관계가 단절됨
- **발생 조건**:
  - 결론이 요약 단계에서 새로 생성됨
  - 근거가 누락되거나 인용 오류 발생
- **완화책**: 결론의 근거 출처 명시 요구 및 자동 검증

## 열린 질문 (Unresolved Questions)

### Q-001
**질문**: 카운터(no-progress, repeated issue) 초기화 조건은 무엇인가?

- **현재 상태**: 증거에서 명시되지 않음
- **영향**: 수렴 가설(H-002) 검증에 필요
- **우선순위**: 높음

### Q-002
**질문**: P0/P1 이슈의 구체적 정의 기준은 무엇인가?

- **현재 상태**: "치명적"이라는 표현만 존재
- **영향**: 검증 기준 모호성 위험(R-004) 해결에 필요
- **우선순위**: 높음

### Q-003
**질문**: repair_loop에서의 "진전(progress)" 판단 기준은 무엇인가?

- **현재 상태**: "실질 개선 없음"이라는 표현만 존재
- **영향**: 종료 조건의 정확도에 영향
- **우선순위**: 중간
