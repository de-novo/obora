# 연구 발견 (Research Findings)

## 요약

GLM-4.7 단일 모델 기반 Obora 워크플로우의 Validation-Repair Loop 메커니즘 분석 결과, 논문급 연구 수행의 **내부 운영 가능성은 확인**되었으나, **외부 타당성 검증과 컨텍스트 붕괴 방지**에 대한 추가 메커니즘이 필요함이 밝혀졌다.

---

## 발견 1: 구조적 발견

### F1-001: V-R Loop의 상태 머신 모델링 가능성

**주장**: Obora의 Validation-Repair Loop는 계층적 상태 머신(Hierarchical State Machine)으로 모델링 가능하다.

**근거 (Evidence)**:
- E-004: V-R Loop 구성요소 명시 (Step, on_fail, repair_loop)
- E-005: repair_loop 설정 구조 (max_iterations, 상태 추적)
- F-001~F-004: 종료/재진입/안전 중단 조건의 명시적 정의

**구조적 특징**:
```
[Top Level]
  Step_n → Validation
           ↓ (FAIL)
           on_fail → repair_loop
                     ↓ (max_reached)
                     Bounded Conclusion
           ↓ (PASS)
           Step_{n+1}

[repair_loop Submachine]
  Remediation → Revalidation → (Success/Failure/Repeat)
```

**시사점**:
- 형식적 검증(formal verification) 가능성: 상태 전이의 완전성 및 도달 가능성(provability) 증명
- 툴링: 상태 머신 시각화 및 디버깅 도구 개발 기반

**한계**:
- 현재 증거는 설정 구조만 제공; 실제 실행 시점의 상태 전이 로그 필요
- 카운터 초기화 조건 명시 부재 (Q-001)

---

## 발견 2: 기능적 발견

### F2-001: 이중 계층 종료 조건의 효과성

**주장**: 성공 종료와 안전 종료의 이중 계층 구조는 무한 루프 위험(R-001)을 효과적으로 완화한다.

**근거 (Evidence)**:
- F-001: 성공 종료는 "모든 필수 기준 만족"으로 정의
- F-002: 재진입은 "FAIL/P0이슈/근거부족 중 하나"로 트리거
- F-003: 안전 중단은 no-progress ceiling=3, repeated issue ceiling=2로 정의
- F-004: max_iterations=5로 상한 설정

**조합 효과**:
| 종료 유형 | 트리거 조건 | 보장 효과 |
|-----------|-------------|-----------|
| 성공 종료 | 3개 질문 답변 + P0 이슈 0개 + 아카이브 완성 | 의도한 목표 달성 시 즉시 종료 |
| 안전 종료 | no-progress 3회 or repeated issue 2회 or max 5회 | 자원 낭비 및 무한 루프 방지 |

**시사점**:
- bounded conclusion을 통한 "최선의 결과 산출" 가능
- 실패 패턴 학습 데이터로 활용 가능

**한계**:
- "진전(progress)" 판단 기준이 모호함 (Q-003)
- 의사 수렴(Pseudo-convergence) 위험(R-002)이 완전히 해결되지 않음

### F2-002: 실패 패턴의 두 가지 유형

**주장**: 실패 신호는 "무시(Ignorance)"와 "반복(Repetition)"으로 분류되며, 각각 다른 보정 전략이 필요하다.

**근거 (Evidence)**:
- T-001~T-003: 검증 대상이 충돌/유지/반영의 3차원
- T-004: 후속 문서의 선행 결정 무시가 실패 신호
- T-005: 동일 결함의 반복이 실패 신호

**실패 패턴 분류**:

| 패턴 | 증상 | 원인 | 보정 전략 |
|------|------|------|-----------|
| 무시형 | 후속 문서가 선행 결정을 반영하지 않음 | 컨텍스트 붕괴 | 명시적 컨텍스트 주입 강제 |
| 반복형 | 동일 결함이 수정되지 않고 재발 | 보정 로고 부족 | 결함 근본 원인 분석 강화 |
| 근거 결핍형 | 결론이 충분한 근거 없이 생성됨 | 요약 과정의 단축 | 근거 출처 명시 의무화 |

**시사점**:
- 실패 패턴별 맞춤형 on_fail 정책 필요
- 반복형 패턴의 경우, 재시도 회수 제한보다는 근본 원인 분석이 우선

## 발견 3: 효과적 발견

### F3-001: 아티팩트 기반 추적성의 향상 효과

**주장**: Obora의 명시적 아티팩트 정책은 단순 프롬프트 체인 대비 연구 흐름의 추적 가능성을 현저히 향상시킨다.

**근거 (Evidence)**:
- research-brief.md: "모든 주요 중간 산출물은 파일로 남긴다"
- research-brief.md: "리뷰 단계는 PASS/FAIL과 이슈 목록을 반드시 남긴다"
- research-brief.md: "remediation 단계는 수정 대상과 수정 이유를 명시한다"
- 02-success-criteria.md: 아카이브 산출물 목록 명시

**추적성 구성요소**:

| 구성요소 | 프롬프트 체인 | Obora 아티팩트 | 향상 효과 |
|----------|---------------|----------------|-----------|
| 중간 결정 | 모델 내부 흡수 | 파일로 영구 저장 | 재구성 가능 |
| 수정 이력 | 프롬프트 히스토리 | 명시적 decision log | 원인 추적 가능 |
| 리뷰 결과 | 메시지로 전달 | PASS/FAIL + 이슈 목록 | 검증 기준 투명 |
| 최종 산출 | 단일 응답 | 아카이브 문서 세트 | 제3자 재현 가능 |

**정성적 평가**:
- 제3자가 연구 흐름을 재구성할 수 있는지: YES (연구 노트 구조화 가능)
- 주장과 한계가 분리되어 있는지: YES (Evidence/Observation/Hypothesis/Risk 구조)
- 결정과 수정 이력이 추적 가능한지: YES (decision log 명시)

**한계**:
- 정량적 측정(30% 향상 등)은 실제 재구성 테스트 필요
- 아티팩트 간의 의존성 추적은 자동화되지 않음 (현재는 수동)

### F3-002: 컨텍스트 붕괴의 위험도

**주장**: iteration 증가에 따른 컨텍스트 붕괴 위험은 존재하나, 명시적 아티팩트 정책이 이를 완화한다.

**근거 (Evidence)**:
- O-005: 컨텍스트 유지가 필수 성공 기준
- H-003: iteration 증가 시 컨텍스트 유지율 감소 예측
- R-003: 컨텍스트 누적 위험 명시

**완화 메커니즘**:
1. **핵심 용어 강제 유지**: 중간 단계의 핵심 용어가 후속 문서에서 유지되는지 검증
2. **판단 기준 명시화**: 각 단계의 판단 기준이 아티팩트에 명시됨
3. **결정 로그 충돌 감지**: 수정 이력에서 충돌을 감지하는 메커니즘 (R-003 완화책)

**시사점**:
- iteration 상한(max=5)은 컨텍스트 붕괴 방지를 위한 실질적 제한
- 아카이브 문서 세트 생성은 최종 컨텍스트 통합 방법

## 가설 검증 결과

### H-001: 구조 가설 → **지지됨**
- **결과**: V-R Loop는 계층적 상태 머신으로 모델링 가능
- **증거**: 구성요소, 의존관계, 종료 조건의 명시적 정의
- **남은 검증**: 실제 실행 로그와 상태 전이 다이어그램 매핑

### H-002: 수렴 가설 → **부분 지지**
- **결과**: ceiling 조합은 대부분 실패 패턴 탐지 가능하나, 진전 판단 기준 모호
- **증거**: 이중 계층 종료 조건의 구조적 완전성
- **남은 검증**: Q-003(진전 판단 기준) 해결 필요

### H-003: 컨텍스트 붕괴 가설 → **검증 보류**
- **결과**: 위험은 존재하나, 실제 iteration별 유지율 데이터 없음
- **증거**: 아티팩트 정책이 완화책으로 기능
- **남은 검증**: iteration 실행 및 유지율 측정 필요

### H-004: 단일 모델 한계 가설 → **지지됨**
- **결과**: 내부 정합성 검증은 충분하나, 외부 타당성 검증은 제한적
- **증거**: research-brief.md의 "논문급 연구의 최소 요건" 충족 가능성
- **남은 검증**: P0/P1 이슈 유형 분석 (Q-002)

### H-005: 추적성 향상 가설 → **지지됨**
- **결과**: 아티팩트 기반 접근은 추적 가능성을 현저히 향상
- **증거**: 연구 흐름 재구성 가능성, 주장/한계 분리, 결정 로그 추적 가능성
- **남은 검증**: 정량적 측정(재구성 테스트) 필요

- **남은 과제**: 결론의 근거 인용 자동 검증

## 평가 질문에 대한 답변

### Q1: GLM-4.7은 단일 모델만으로도 논문형 연구 워크플로우를 수렴시킬 수 있는가?

**답변**: **예, 내부 운영 가능성은 확인됨.**

**근거**:
- 구조적: V-R Loop가 상태 머신으로 모델링 가능 (F1-001)
- 기능적: 이중 계층 종료 조건이 수렴 보장 (F2-001)
- 효과적: 아티팩트 기반 추적성이 논문형 요건 충족 (F3-001)

**제한**:
- 외부 타당성 검증(학술적 검증)은 제한적 (H-004)
- 컨텍스트 붕괴 위험은 iteration 5 이상에서 높아질 가능성 (H-003)

### Q2: 동일 모델 다중 reviewer가 논문형 품질 게이트로 의미가 있는가?

**답변**: **부분적으로 의미가 있으나, 기준의 명확화가 필요함.**

**근거**:
- 단일 모델 자가 검증은 편향 가능성 존재 (R-004)
- P0/P1 이슈 분류 기준이 모호함 (Q-002)
- 실패 패턴 분류(무시형/반복형/근거결핍형)는 유용함 (F2-002)

**개선 필요**:
- 정량적 검증 기준 정의
- 교차 검증(cross-validation) 메커니즘 추가

**한계**:

- 보정력의 정량적 측정 필요

**경계 조건**:
- iteration 5 이상에서는 컨텍스트 붕괴 위험 증가 (H-003)
- 동일 결함 반복 시 정합성 저하 가능성 (R-003)

## 결론

### 주 결론
1. GLM-4.7 단일 모델 기반 Obora는 논문급 연구 수행의 **내부 운영 가능성을 입증**했다.
2. Validation-Repair Loop는 계층적 상태 머신으로 모델링 가능하며, 이중 계층 종료 조건이 안정성을 보장한다.
3. 아티팩트 기반 접근은 단순 프롬프트 체인 대비 **추적성, 보정력, 재현성에서 현저한 향상**을 제공한다.

### 한계
1. **외부 타당성 검증**: 학술적 검증은 제한적; 추가 메커니즘 필요
2. **검증 기준 모호성**: P0/P1 이슈 분류 기준의 정량화 필요
3. **컨텍스트 붕괴**: iteration 5 이상에서 위험 증가; 상한 유지 필요

### 후속 연구 제안
1. **Q-001 해결**: 카운터 초기화 조건 명시 및 구현
2. **Q-002 해결**: P0/P1 이슈 정의 기준 정량화
3. **Q-003 해결**: 진전(progress) 판단 기준 정의
4. **H-003 검증**: iteration별 컨텍스트 유지율 실측
5. **R-002 완화**: 의사 수렴 방지를 위한 의미 수준 검증 방법론
6. **정량적 평가**: 재구성 테스트를 통한 추적성 향상 정도 측정
