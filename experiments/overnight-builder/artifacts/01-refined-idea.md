# Refined Idea: CLI 할 일 관리 도구 (Todo CLI)

작성일: 2026-03-20  
Cycle: 1

---

## 1. 프로젝트 개요

**제품명**: Todo CLI  
**목표**: 로컬 환경에서 동작하는 프로덕션급 CLI 할 일 관리 도구 구축

### 핵심 가치
- **신뢰성**: 데이터 손실 없는 안정적인 저장
- **사용성**: 직관적이고 일관된 CLI UX
- **품질**: 100% 테스트 커버리지와 명확한 에러 처리

### 기술 스택
- 언어: TypeScript (strict mode)
- 런타임: Node.js 20+
- 패키지 매니저: npm
- 테스트 프레임워크: node:test (내장)
- 저장: 로컬 JSON 파일 (`~/.todo-cli/todos.json`)
- CLI 프레임워크: 순수 Node.js (의존성 최소화)

### 프로젝트 구조
```
workspace/
├── package.json
├── tsconfig.json
├── src/
│   ├── index.ts          # 진입점
│   ├── cli.ts            # CLI 인터페이스
│   ├── commands/         # 각 명령어 구현
│   ├── services/         # 비즈니스 로직
│   ├── storage.ts        # JSON 저장소
│   └── types.ts          # 타입 정의
├── tests/                # 테스트 파일
└── README.md
```

## 2. 이번 Cycle에서 구현할 기능

### 기능 1: 핵심 CRUD 명령어 (프로덕션급)

**명령어 목록**:
- `todo add <내용>` - 할 일 추가
- `todo list [--all]` - 할 일 목록 조회 (기본: 미완료만)
- `todo done <ID>` - 할 일 완료 처리
- `todo remove <ID>` - 할 일 삭제

**프로덕션 품질 요소**:
- [ ] ID 생성: 타임스탬프 기반 고유 ID (충돌 방지)
- [ ] 데이터 검증: 입력 길이 제한 (1-500자), 빈 입력 거부
- [ ] 에러 메시지: 사용자 친화적 메시지 + 종료 코드
- [ ] 동시성: 파일 잠금으로 데이터 손상 방지
- [ ] 출력 포맷팅: 가독성 있는 테이블 형태

### 기능 2: 저장소 신뢰성 시스템

**구현 내용**:
- [ ] 자동 백업: 변경 전 이전 상태 백업 (`todos.json.bak`)
- [ ] 마이그레이션: 스키마 버전 관리
- [ ] 복구: 손상된 데이터 감지 및 복구 안내
- [ ] 초기화: 첫 실행 시 저장소 자동 생성

## 3. 프로덕션 품질 기준

### 3.1 에러 핸들링

| 에러 유형 | 처리 방식 | 종료 코드 |
|----------|----------|-----------|
| 잘못된 명령어 | 사용법 안내 + 에러 메시지 | 1 |
| 존재하지 않는 ID | "ID를 찾을 수 없습니다" 메시지 | 1 |
| 파일 읽기/쓰기 실패 | 구체적 에러 + 해결 방안 | 2 |
| 잘못된 입력값 | 검증 에러 메시지 | 1 |
| 손상된 데이터 파일 | 백업에서 복구 안내 | 3 |

### 3.2 엣지 케이스

- [ ] 빈 할 일 목록 처리 ("할 일이 없습니다" 메시지)
- [ ] 매우 긴 할 일 내용 (500자 초과 시 거부)
- [ ] 특수문자/이모지 포함 내용 (UTF-8 지원)
- [ ] 동시 실행 방지 (파일 잠금)
- [ ] 디스크 용량 부족 시 안전한 실패
- [ ] 존재하지 않는 저장 디렉토리 자동 생성

### 3.3 UX 기준

- [ ] 모든 명령어 `--help` 플래그 지원
- [ ] 일관된 출력 포맷 (색상, 정렬)
- [ ] 진행 상황 피드백 (완료 메시지)
- [ ] 친화적 에러 메시지 (기술 용어 최소화)
- [ ] 버전 정보 (`--version`)

### 3.4 테스트 기준

- [ ] 단위 테스트: 모든 서비스 함수
- [ ] 통합 테스트: 전체 명령어 플로우
- [ ] 엣지 케이스 테스트: 에러 시나리오
- [ ] 커버리지: 핵심 로직 100%

## 부록: 명령어 상세 스펙

### `todo add <내용>`
```
입력: todo add "프로젝트 기획서 작성"
출력: ✓ 할 일이 추가되었습니다 (ID: 1712345678901)
에러: 
  - 내용이 비어있음 → "할 일 내용을 입력하세요"
  - 500자 초과 → "할 일은 500자 이내로 입력하세요"
```

### `todo list [--all]`
```
입력: todo list
출력: 
  ┌──────────────┬──────────────────────────┬──────────┐
  │ ID           │ 할 일                     │ 상태     │
  ├──────────────┼──────────────────────────┼──────────┤
  │ 171234567890 │ 프로젝트 기획서 작성       │ 진행중   │
  └──────────────┴──────────────────────────┴──────────┘
  총 1개 할 일

입력: todo list --all
  (완료된 항목 포함 표시)
```

### `todo done <ID>`
```
입력: todo done 1712345678901
출력: ✓ "프로젝트 기획서 작성" 완료 처리되었습니다
에러:
  - ID 없음 → "ID '1712345678901'를 찾을 수 없습니다"
```

### `todo remove <ID>`
```
입력: todo remove 1712345678901
출력: ✓ "프로젝트 기획서 작성" 삭제되었습니다
에러:
  - ID 없음 → "ID '1712345678901'를 찾을 수 없습니다"
```
