## 1. 프로젝트 개요

### 1.1 비전

TaskVault는 로컬 환경에서 동작하는 프로덕션급 CLI 할 일 관리 도구입니다. 외부 서비스 의존 없이 개인 사용자가 자신의 터미널에서 빠르고 안정적으로 업무를 관리할 수 있도록 설계되었습니다.

### 1.2 현재 상태 (Cycle 2 완료)

| 기능 영역 | 상태 | 구현 내용 |
|-----------|------|-----------|
| Core CRUD | ✅ 완료 | add, list, done, delete |
| 검색 | ✅ 완료 | 키워드 검색, 상태/태그 필터, 정확 매칭 |
| 태그 시스템 | ✅ 완료 | 태그 추가/제거/조회, 태그별 필터링 |
| 영속성 | ✅ 완료 | JSON 파일 저장, 원자적 쓰기, 마이그레이션 |
| 에러 핸들링 | ✅ 완료 | 22개 에러 코드, 한국어 메시지 |
| 테스트 | ✅ 완료 | 230+ 테스트 케이스, 85%+ 커버리지 |
| 문서화 | ✅ 완료 | 완전한 README, JSDoc 주석 |

### 1.3 기술 스택

- **언어**: TypeScript (strict mode)
- **런타임**: Node.js 18+
- **패키지 매니저**: npm
- **테스트 프레임워크**: Vitest
- **외부 의존성**: 없음 (zero runtime dependencies)

### 1.4 아키텍처 요약

```
4-Layer Clean Architecture
├── CLI Layer (index.ts) - 인자 파싱, 명령어 라우팅
├── Command Layer (commands/*.ts) - 입력 검증, 서비스 호출
├── Service Layer (TaskService.ts) - 비즈니스 로직
└── Storage Layer (JsonStorage.ts) - 영속성, 원자적 쓰기
```

## 2. 이번 Cycle에서 추가/개선할 기능

### 2.1 기능 1: 마감일 시스템 (Due Dates)

**사용자 가치**:
- 할 일에 마감일을 설정하여 시간 관리 가능
- 마감일 기준 정렬로 우선순위 파악 용이
- 기한 초과 태스크 시각적 표시

**기능 명세**:

| 명령어 | 설명 | 예시 |
|--------|------|------|
| `taskvault add "내용" --due YYYY-MM-DD` | 마감일과 함께 태스크 추가 | `taskvault add "보고서 작성" --due 2026-03-25` |
| `taskvault list --overdue` | 기한 초과 태스크만 표시 | `taskvault list --overdue` |
| `taskvault list --due-soon` | 7일 내 마감 태스크 표시 | `taskvault list --due-soon` |
| `taskvault list --sort due` | 마감일 기준 정렬 | `taskvault list --sort due` |
| `taskvault edit <id> --due YYYY-MM-DD` | 마감일 수정 | `taskvault edit 1 --due 2026-03-30` |

**데이터 모델 변경**:

```typescript
interface Task {
  id: number;
  content: string;
  completed: boolean;
  tags: string[];
  createdAt: string;
  updatedAt: string;
  dueDate?: string | null;  // NEW: ISO 8601 (YYYY-MM-DD) or null
}
```

**마이그레이션 전략**:
- 기존 태스크는 `dueDate: null`로 자동 설정
- 버전 0.1.0 → 0.2.0 자동 마이그레이션
- 하위 호환성 100% 보장

### 2.2 기능 2: 우선순위 시스템 (Priority Levels)

**사용자 가치**:
- 태스크 중요도 구분으로 업무 우선순위 관리
- 우선순위별 필터링으로 중요 업무 집중
- 시각적 구분(색상 또는 표시)으로 인지성 향상

**기능 명세**:

| 명령어 | 설명 | 예시 |
|--------|------|------|
| `taskvault add "내용" --priority <level>` | 우선순위와 함께 태스크 추가 | `taskvault add "긴급 버그 수정" --priority high` |
| `taskvault list --priority <level>` | 특정 우선순위 태스크만 표시 | `taskvault list --priority high` |
| `taskvault list --sort priority` | 우선순위 기준 정렬 | `taskvault list --sort priority` |
| `taskvault edit <id> --priority <level>` | 우선순위 수정 | `taskvault edit 1 --priority medium` |

**우선순위 레벨**:

| 레벨 | 키워드 | 표시 | 순서 |
|------|--------|------|------|
| 높음 | `high`, `h`, `1` | 🔴 [HIGH] | 1 (최우선) |
| 보통 | `medium`, `m`, `2` | 🟡 [MEDIUM] | 2 |
| 낮음 | `low`, `l`, `3` | 🟢 [LOW] | 3 |
| 없음 | (미지정) | (표시 없음) | 4 (기본값) |

**데이터 모델 변경**:

```typescript
type Priority = 'high' | 'medium' | 'low' | null;

interface Task {
  id: number;
  content: string;
  completed: boolean;
  tags: string[];
  createdAt: string;
  updatedAt: string;
  dueDate?: string | null;
  priority?: Priority;  // NEW: high | medium | low | null
}
```

**마이그레이션 전략**:
- 기존 태스크는 `priority: null`로 자동 설정
- 버전 0.2.0으로 자동 마이그레이션
- 하위 호환성 100% 보장

## 3. 프로덕션 품질 기준

### 3.1 에러 핸들링 요구사항

#### 3.1.1 마감일 관련 에러

| 에러 코드 | 메시지 | 복구 가이드 |
|-----------|--------|-------------|
| `DUE_001` | 마감일 형식이 올바르지 않습니다. | YYYY-MM-DD 형식으로 입력해주세요. 예: --due 2026-03-25 |
| `DUE_002` | 유효하지 않은 날짜입니다. | 실제 존재하는 날짜를 입력해주세요. |
| `DUE_003` | 마감일은 1년 이내로 설정해주세요. | 너무 먼 미래의 날짜는 설정할 수 없습니다. |
| `DUE_004` | 이미 지난 날짜는 마감일로 설정할 수 없습니다. | 오늘 이후의 날짜를 입력해주세요. (또는 --allow-past 플래그 사용) |

#### 3.1.2 우선순위 관련 에러

| 에러 코드 | 메시지 | 복구 가이드 |
|-----------|--------|-------------|
| `PRIORITY_001` | 유효하지 않은 우선순위입니다. | high, medium, low 중 하나를 입력해주세요. |
| `PRIORITY_002` | 우선순위 값이 너무 깁니다. | h, m, l 또는 high, medium, low를 사용해주세요. |

#### 3.1.3 공통 에러 처리 원칙

1. **모든 에러는 복구 가능해야 함**: 크래시 없이 명확한 가이드 제공
2. **한국어 메시지**: 사용자 친화적 메시지
3. **컨텍스트 포함**: 현재 입력값, 허용 값 등 포함
4. **Exit code**: 성공 0, 에러 1 일관성 유지

#### 3.2.1 마감일 엣지 케이스

| 케이스 | 입력 | 기대 동작 |

| 공백만 | `--due "   "` | DUE_001 에러 |
| 잘못된 형식 | `--due "2026/03/25"` | DUE_001 에러 |
| 존재하지 않는 날짜 | `--due "2026-02-30"` | DUE_002 에러 |
| 윤년 경계 | `--due "2024-02-29"` | ✅ 정상 처리 |
| 연말 연초 | `--due "2026-12-31"` | ✅ 정상 처리 |
| 오늘 날짜 | `--due "2026-03-18"` | ✅ 정상 처리 |
| 과거 날짜 | `--due "2020-01-01"` | DUE_004 에러 (또는 경고) |

|--------|------|-----------|

### 3.3 사용자 경험 기준

#### 3.3.1 출력 포맷팅

**마감일 표시**:
```
[1] 보고서 작성                    🔴 [HIGH] 📅 2026-03-25 (2일 남음)
[2] 코드 리뷰                      🟡 [MEDIUM] 📅 2026-03-20 (기한 초과!)
[3] 문서 업데이트                  🟢 [LOW] 📅 2026-04-01 (14일 남음)
[4] 일반 태스크                    (마감일 없음)
```

**우선순위 표시**:
- 🔴 HIGH: 빨간색 이모지, [HIGH] 라벨
- 🟡 MEDIUM: 노란색 이모지, [MEDIUM] 라벨
- 🟢 LOW: 초록색 이모지, [LOW] 라벨
- (없음): 이모지/라벨 없음

**기한 초과 강조**:
- 기한 초과 태스크는 "⚠️ 기한 초과!" 메시지 표시
- 남은 일수가 음수인 경우 빨간색 강조

#### 3.3.2 피드백 메시지

| 상황 | 메시지 |
|------|--------|
| 태스크 추가 성공 | ✅ 태스크가 추가되었습니다. (ID: 5, 마감일: 2026-03-25, 우선순위: 높음) |
| 마감일 수정 성공 | ✅ 마감일이 변경되었습니다. (2026-03-18 → 2026-03-30) |
| 우선순위 수정 성공 | ✅ 우선순위가 변경되었습니다. (보통 → 높음) |
| 기한 초과 태스크 없음 | ✅ 기한이 초과된 태스크가 없습니다. |
| 7일 내 마감 태스크 없음 | ✅ 7일 내 마감일이 있는 태스크가 없습니다. |

#### 3.3.3 CLI 사용성

1. **단축 옵션 지원**: `--due` → `-d`, `--priority` → `-p`
2. **자동 완성 가이드**: 잘못된 입력 시 올바른 예시 제시
3. **일관된 출력 포맷**: 기존 list 출력과 시각적 일관성 유지
4. **도움말 업데이트**: `--help`에 새 옵션 추가
