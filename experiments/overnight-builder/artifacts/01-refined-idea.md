# Refined Idea: CLI Todo Manager

## 1. 프로젝트 개요

**프로젝트명**: `todocli` - CLI 기반 할 일 관리 도구

**목표**: 프로덕션 수준의 안정적이고 사용자 친화적인 CLI 할 일 관리자를 구축한다. JSON 파일로 로컬 저장하며, 직관적인 명령어와 명확한 피드백을 제공한다.

**기술 스택**:
- TypeScript + Node.js
- npm (패키지 매니저)
- vitest (테스트 프레임워크)
- Commander.js 또는 yargs (CLI 프레임워크)
- 로컬 JSON 파일 저장

**핵심 가치**:
- **신뢰성**: 데이터 손실 없음, 모든 에러 상황 처리
- **사용성**: 직관적 명령어, 명확한 피드백
- **유지보수성**: 테스트 커버리지, 문서화

---

## 2. 이번 Cycle에서 추가/개선할 기능 (Cycle 1)

### 기능 1: 핵심 CRUD 명령어 구현
할 일 관리의 기본 기능을 프로덕션 수준으로 구현한다.

**명령어**:
```bash
todocli add <제목>           # 할 일 추가
todocli list [--all]         # 할 일 목록 (기본: 미완료만, --all: 전체)
todocli done <id>            # 완료 처리
todocli undo <id>            # 완료 취소
todocli remove <id>          # 삭제
todocli clear                # 완료된 항목 일괄 삭제
```

**데이터 모델**:
```typescript
interface Todo {
  id: string;        // UUID v4
  title: string;     // 최대 200자
  completed: boolean;
  createdAt: string; // ISO 8601
  completedAt?: string;
}
```

### 기능 2: 견고한 에러 핸들링 및 사용자 피드백
프로덕션 수준의 UX를 위해 모든 에러 상황을 처리하고 명확한 피드백을 제공한다.

## 3. 프로덕션 품질 기준

### 3.1 에러 핸들링

**파일 시스템 에러**:
- [ ] 데이터 파일이 없을 경우 자동 생성
- [ ] 파일 읽기/쓰기 권한 없을 때 명확한 에러 메시지
- [ ] 디스크 용량 부족 시 안전한 실패 (기존 데이터 보존)
- [ ] 파일이 손상된(JSON 파싱 실패) 경우 복구 옵션 제공

**입력 검증**:
- [ ] 빈 제목 금지 (공백만 있는 경우도 포함)
- [ ] 제목 길이 제한 (200자)
- [ ] 존재하지 않는 ID 참조 시 명확한 에러
- [ ] 중복 생성 방지는 하지 않음 (사용자 의도 허용)

**명령어 에러**:
- [ ] 잘못된 명령어 입력 시 도움말 표시
- [ ] 필수 인자 누락 시 사용법 안내
- [ ] unknown 옵션 처리

### 3.2 엣지 케이스

- [ ] **빈 목록**: 할 일이 없을 때 "할 일이 없습니다" 메시지
- [ ] **특수 문자**: 제목에 이모지, 한글, 특수문자 허용
- [ ] **동시성**: 여러 터미널에서 동시 실행 시 데이터 무결성 보장 (파일 잠금 또는 재시도)
- [ ] **대량 데이터**: 1000개 이상의 할 일 처리 시 성능 저하 없음
- [ ] **시스템 중단**: 쓰기 중단 시 데이터 무결성 (원자적 쓰기)
- [ ] **ID 충돌**: UUID v4로 사실상 불가능하지만 검증 로직 포함

### 3.3 UX 기준

**명확한 피드백**:
- [ ] 모든 작업에 성공/실패 메시지 (색상 구분)
- [ ] `list` 명령은 테이블 형태로 가독성 있게 표시
- [ ] 완료된 항목은 취소선 또는 별도 표시
- [ ] ID는 앞 8자리만 표시 (전체 ID는 `--verbose` 옵션)

**도움말**:
- [ ] `--help` for each command
- [ ] 예시 포함
- [ ] 버전 정보 (`--version`)

**출력 형식**:
```
✓ 할 일이 추가되었습니다: "프로젝트 기획안 작성" (a1b2c3d4)
✓ 완료 처리되었습니다: "프로젝트 기획안 작성"
✗ 할 일을 찾을 수 없습니다: e5f6g7h8
```

## 5. 전체 프로젝트 진행률 추정

### 전체 예상 Cycles: 3~4개

| Cycle | 주요 작업 | 예상 완료도 |
|-------|----------|-----------|
| **Cycle 1** (현재) | 핵심 CRUD + 에러 핸들링 + 기본 테스트 | 50% |
| Cycle 2 | 고급 기능 (검색, 태그, 우선순위) + 테스트 보강 | 75% |
| Cycle 3 | UX 개선 (색상, 포맷팅) + 문서화 완성 | 90% |
| Cycle 4 (선택) | 버그 수정, 리팩토링, 배포 준비 | 100% |

### 현재 상태: **0% → 목표 50%**

**이번 Cycle 성공 기준**:
1. 모든 기본 명령어가 프로덕션 수준으로 동작
2. 핵심 엣지 케이스 100% 처리
