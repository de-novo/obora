# Agent Independence Rule

에이전트 정의 파일 작성 시 적용되는 독립성 규칙입니다.

## 핵심 원칙

**에이전트는 다른 에이전트의 존재를 알아선 안 됩니다.**

```yaml
이유:
  - 에이전트는 추가/삭제/변경될 수 있음
  - 에이전트 간 결합(coupling)은 유지보수를 어렵게 함
  - planner가 에이전트 선택을 담당함
  - 각 에이전트는 자신의 책임만 정의
```

## 금지 패턴

### 1. 특정 에이전트 이름 언급

```markdown
# 금지
- 보안 검토 (security-auditor에게 위임)
- 테스트 작성 (test-writer 에이전트 사용)
- debugger 에이전트와 협력

# 허용
- 보안 검토 (이 에이전트의 책임 범위 외)
- 테스트 작성 (책임 범위 외)
```

### 2. 위임 표현

```markdown
# 금지
- ~담당 에이전트에게 위임
- ~에이전트가 처리
- ~에이전트를 사용하세요

# 허용
- 이 에이전트의 책임 범위 외
- 책임 범위 외
- (이 에이전트가) 수행하지 않음
```

### 3. 다른 에이전트 참조

```markdown
# 금지
참조: reviewer, security-auditor
관련 에이전트: debugger

# 허용
(참조 섹션 자체를 두지 않음)
```

## 허용 패턴

### "하지 않는 것" 섹션 작성법

```markdown
## 하지 않는 것

- 코드 직접 수정 (이 에이전트의 책임 범위 외)
- 테스트 실행 (책임 범위 외)
- 보안 검토 (책임 범위 외)
```

### description 작성법

```yaml
# 금지
description: 코드 리뷰. security-auditor와 함께 사용.

# 허용
description: 코드 품질 검토. 가독성, 성능 리뷰 시 사용.
```

## 검증 방법

에이전트 파일 작성/수정 시 확인:

```bash
# 금지 패턴 검색
Grep: "에이전트에게 위임|에이전트를 사용|에이전트와 협력" in .claude/agents/

# 특정 에이전트 이름 검색 (하이픈 포함 이름)
Grep: "reviewer|debugger|implementer|security-auditor" in .claude/agents/
```

## 예외

### 공용 원칙 파일

`_shared-principles.md` 같은 공용 파일은 에이전트 목록을 참조할 수 있습니다.
단, 개별 에이전트 파일에서는 불가.

### planner 에이전트

planner는 다른 에이전트를 선택하는 역할이므로 에이전트 목록을 받을 수 있습니다.
단, 하드코딩이 아닌 동적으로 전달받아야 함.

## 요약

```yaml
원칙:
  - 에이전트는 자신의 책임만 정의
  - 다른 에이전트 존재/이름 언급 금지
  - "위임" 대신 "책임 범위 외" 사용

예외:
  - 공용 원칙 파일
  - planner (동적으로 전달받는 경우만)
```
