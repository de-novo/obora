# Interview - Requirements Discovery

**사용자와 대화형 인터뷰를 통해 요구사항을 명확화합니다.**

## 사용 시점

- 모호한 요청을 구체화할 때
- 새 기능 구현 전 요구사항 정의 시
- 복잡한 비즈니스 로직 파악 시
- 엣지 케이스 발견이 필요할 때

## 실행 절차

### 1. Interviewer 에이전트 직접 호출

```
Task(subagent_type="interviewer", prompt="
요구사항 인터뷰 진행:

사용자 요청: $ARGUMENTS

다음 단계로 진행:
1. 코드베이스 맥락 파악 (Glob, Read로 관련 코드 확인)
2. 핵심 요구사항 도출 (AskUserQuestion으로 질문)
3. 세부사항 탐색 (입력/출력/검증/에러처리)
4. 엣지 케이스 발견
5. 우선순위 결정 (Must/Should/Could/Won't)
6. 요구사항 명세서 작성

결과물:
- 구조화된 요구사항 명세서
- 관련 기존 코드 참조 목록
- 미결정 사항 목록
")
```

### 2. 결과 활용

인터뷰 완료 후 사용자 선택:

```yaml
옵션:
  A: 바로 구현 진행 → /implement [요구사항 명세서 기반]
  B: 추가 인터뷰 필요 → 후속 질문
  C: 요구사항 저장 → 문서로 보관
```

## 예시

### 입력

```
/interview 사용자 로그인 기능 추가
```

### 인터뷰 진행

```
Q1: 이 기능의 주요 사용자는 누구인가요?
    [일반 사용자] [관리자] [비로그인 사용자]

Q2: 로그인 방식은 어떤 것을 원하시나요?
    [이메일/비밀번호] [소셜 로그인] [SSO]

Q3: 로그인 실패 시 어떻게 처리할까요?
    [에러 메시지만] [재시도 제한] [계정 잠금]

...
```

### 출력

```markdown
# 요구사항 명세서: 사용자 로그인

## 개요
- 목적: 사용자 인증 및 세션 관리
- 사용자: 일반 회원
- 트리거: 로그인 버튼 클릭

## 기능 요구사항
- FR-001: 이메일/비밀번호 로그인 (Must Have)
- FR-002: 소셜 로그인 - Google (Should Have)
- FR-003: 비밀번호 재설정 (Must Have)

## 엣지 케이스
- EC-001: 5회 연속 실패 → 5분 잠금
- EC-002: 세션 만료 → 자동 로그아웃
...
```

## 특징

- **대화형**: AskUserQuestion으로 실시간 질문
- **컨텍스트 기반**: 기존 코드 패턴 참조
- **구조화된 출력**: 표준 요구사항 명세서 형식
- **후속 작업 연계**: /implement로 바로 구현 가능
- **세션 간 지속성**: DB에 자동 저장되어 다음 세션에서도 사용 가능

## 세션 간 연계

```yaml
저장:
  - 인터뷰 결과는 workflows.output에 자동 저장됨
  - Hook이 자동으로 처리 (별도 작업 불필요)

조회:
  - 다음 세션에서 /implement 실행 시 자동으로 최근 인터뷰 확인
  - 24시간 이내 인터뷰 결과가 있으면 planner에게 전달
  - 인터뷰를 다시 할 필요 없음

워크플로우:
  세션1: /interview "대시보드 기능" → 요구사항 명세서 작성 → DB 저장
  세션2: /implement "대시보드 기능" → DB에서 요구사항 조회 → planner에게 전달 → 구현
```

## 주의사항

```yaml
원칙:
  - 가정하지 않고 질문하기
  - 모호함 발견 시 즉시 명확화
  - 사용자 답변을 요약하여 확인
  - 최종 출력은 "# 요구사항 명세서:" 로 시작

금지:
  - 기술적 결정 강요
  - 요구사항 임의 추가
  - 불명확한 채로 진행
```
