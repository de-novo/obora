# obora-kit v3 Overview

> 버전: v3 (설계 단계)
> 최종 수정: 2026-02-03

---

## 프로젝트 목표

obora-kit은 **AI 에이전트 기반 워크플로우 자동화 도구**입니다.

### 핵심 가치

- **Spec-First 개발 방법론 지원**: 스펙 없이 구현 없다
- **워크플로우 자동화**: 설계 → 구현 → 테스트 → 리뷰 파이프라인
- **OpenClaw 연동**: AI 에이전트를 통한 작업 실행
- **추적 가능한 개발**: 모든 결정과 작업이 기록됨

### 타겟 사용자

| 레벨 | 사용자 | 사용 방식 |
|------|--------|----------|
| 개인 | 솔로 개발자 | 내장 워크플로우로 빠르게 시작 |
| 팀 | 스타트업 팀 | 커스텀 워크플로우 + 공유 에이전트 |
| 기업 | 대규모 조직 | 팀별 워크플로우 + 승인 게이트 |

---

## 8원칙

obora-kit의 설계와 구현은 8가지 원칙을 따릅니다.

| # | 원칙 | 설명 | 적용 |
|---|------|------|------|
| 1 | **Fluid** | 단계 자유롭게 수정/건너뛰기 | 워크플로우 중간 단계 스킵 가능 |
| 2 | **Iterative** | 실패해도 재시도, 반복 | retry 설정, 복구 명령어 |
| 3 | **Easy** | 한 줄로 시작 | `obora init && obora run` |
| 4 | **Brownfield** | 기존 프로젝트에도 적용 | 점진적 도입, 기존 문서 import |
| 5 | **Scalable** | 개인 → 팀 → 기업 | 레벨별 확장 가능 |
| 6 | **Traceable** | 모든 작업은 기록된다 | FileTracker + DBTracker |
| 7 | **SSOT** | 단일 원천 | 파일(정의) + DB(기록) 분리 |
| 8 | **Spec-First** | 스펙 없이 구현 없다 | proposal.md, design.md 필수 |

## 핵심 컴포넌트

### 패키지 구조

```
obora-kit/
├── packages/
│   ├── @obora/cli          # CLI 패키지
│   ├── @obora/core         # 코어 로직
│   └── @obora/database     # DuckDB 연동
└── package.json            # 모노레포 루트
```

### @obora/cli

사용자 인터페이스 담당

| 명령어 | 설명 |
|--------|------|
| `obora init` | 프로젝트 초기화 |
| `obora new` | 새 기능 폴더 생성 |
| `obora plan` | AI로 스펙 생성 |
| `obora run` | 워크플로우 실행 |
| `obora status` | 실행 상태 확인 |
| `obora done` | 완료 및 아카이브 |

### @obora/core

핵심 비즈니스 로직

| 컴포넌트 | 역할 | 관련 원칙 |
|----------|------|-----------|
| Spec Validator | 스펙 문서 검증 | Spec-First |
| Workflow Parser | YAML 파싱, 실행 계획 생성 | Fluid |
| Agent Registry | 에이전트 정의 관리 | SSOT |
| Dependency Resolver | 의존성 분석, 병렬/순차 판단 | Scalable |
| Tracker | 실행 기록 (File + DB) | Traceable |

### @obora/database

데이터 영속성 담당

- DuckDB 연결 관리
- 스키마 마이그레이션
- 쿼리 유틸리티

## 기술 스택

### 런타임

| 기술 | 버전 | 용도 |
|------|------|------|
| **TypeScript** | 5.x | 주 개발 언어 |
| **Node.js** | 18+ | 런타임 환경 |
| **pnpm** | 8+ | 패키지 매니저 (모노레포) |

### 데이터베이스

| 기술 | 버전 | 용도 |
|------|------|------|
| **DuckDB** | 0.9+ | 임베디드 분석 DB |
| **YAML** | 1.2 | 워크플로우 정의 |
| **Markdown** | - | 에이전트/스펙 정의 |

### 선택 이유

**DuckDB를 선택한 이유:**
- ✅ DB 서버 설치 불필요 (임베디드)
- ✅ SQL 쿼리 지원 (분석 친화적)
- ✅ 컬럼 지향 (메트릭 분석에 최적)
- ✅ 파일 기반 (.db 파일 하나)

**YAML을 선택한 이유:**
- ✅ 사람이 읽기 쉬움
- ✅ Git diff 친화적
- ✅ 주석 지원
- ✅ 생태계 성숙 (JSON Schema 등)

### 데이터 흐름

```
obora new    → .obora/features/<name>/ 생성
      ↓
obora plan   → AI가 proposal.md, design.md 생성
      ↓
obora run    → 워크플로우 실행 (OpenClaw 연동)
      ↓
obora done   → archive/로 이동, Git commit
```

## SSOT 전략

### 이중 SSOT

| 구분 | 저장소 | 내용 | Git 관리 |
|------|--------|------|----------|
| **SSOT-정의** | 파일 시스템 | 워크플로우, 에이전트, 스펙 | ✅ |
| **SSOT-기록** | DuckDB | 실행 기록, 메트릭, 통계 | ❌ |

### 분리 이유

- **정의 파일**: 버전 관리 필요 → Git
- **실행 기록**: 분석/쿼리 필요 → DB

## Quick Start

### 설치

```bash
npm install -g @obora/cli
```

### 시작하기

```bash
# 1. 프로젝트 초기화
cd my-project
obora init

# 2. 새 기능 시작
obora new login-feature

# 3. 스펙 작성 (AI 지원)
obora plan

# 4. 워크플로우 실행
obora run

# 5. 완료 및 아카이브
obora done
```

### 최소 요구사항

- Node.js 18+
- 프로젝트 폴더 (빈 폴더도 가능)
