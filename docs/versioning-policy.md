# Versioning Policy

## 목적
obora-kit 모노레포 패키지의 버전 규칙을 통일하여 릴리즈 예측 가능성을 높입니다.

## SemVer 규칙
모든 패키지는 **Semantic Versioning (MAJOR.MINOR.PATCH)** 를 따릅니다.

- **MAJOR**: 하위 호환을 깨는 API/행동 변경
- **MINOR**: 하위 호환을 유지하는 기능 추가
- **PATCH**: 하위 호환을 유지하는 버그 수정/문서·내부 개선

## Pre-release 정책
- 실험/검증 단계 릴리즈는 pre-release 태그 사용:
  - 예: `1.4.0-alpha.1`, `1.4.0-beta.2`, `1.4.0-rc.1`
- pre-release는 안정 버전 대비 호환성 보장이 제한될 수 있습니다.
- 안정화 완료 시 동일 기준의 정식 버전으로 승격합니다.

## 패키지 간 버전 동기화
- 모노레포 운영 단순화를 위해 기본적으로 **동기 버전 전략**을 사용합니다.
- 동일 릴리즈 배치에 포함되는 핵심 패키지는 같은 버전으로 함께 올립니다.
- 예외적으로 독립 릴리즈가 필요한 경우, 변경 영향 범위와 의존성 호환성을 릴리즈 노트에 명시합니다.

## 릴리즈 노트 원칙
- 모든 릴리즈는 변경사항을 다음으로 분류합니다:
  - Breaking Changes
  - Features
  - Fixes
  - Docs/Chore
- 사용자 영향이 있는 변경은 마이그레이션 가이드를 포함합니다.
