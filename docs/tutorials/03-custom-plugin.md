# Tutorial 03: Building a Custom Plugin

**Estimated time:** 20 minutes  
**Audience:** Developers who want to extend Obora

## What you'll learn

In this tutorial, we'll build and use a custom Obora plugin.

You'll go through:

- Implementing the `OboraPlugin` interface for a pattern plugin
- Creating a minimal npm package structure
- Registering plugin metadata
- Using the plugin in a workflow
- Testing plugin behavior

## Prerequisites

- You completed [Tutorial 01](./01-first-workflow.md)
- Familiarity with TypeScript basics
- Node.js 20+

---

## Step 1) Create a plugin package skeleton

Let's create a local package for your plugin:

```bash
mkdir -p plugins/obora-plugin-custom-summary/src
cat > plugins/obora-plugin-custom-summary/package.json << 'EOF'
{
  "name": "obora-plugin-custom-summary",
  "version": "0.1.0",
  "private": true,
  "type": "module",
  "main": "dist/index.js",
  "types": "dist/index.d.ts",
  "scripts": {
    "build": "tsc -p tsconfig.json"
  },
  "devDependencies": {
    "typescript": "^5.6.3"
  }
}
EOF

cat > plugins/obora-plugin-custom-summary/tsconfig.json << 'EOF'
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ES2022",
    "moduleResolution": "Bundler",
    "declaration": true,
    "outDir": "dist",
    "strict": true,
    "skipLibCheck": true
  },
  "include": ["src"]
}
EOF
```

---

## Step 2) Implement the plugin (`OboraPlugin` + pattern execute)

Now we'll implement a minimal pattern plugin in `src/index.ts`.

```bash
cat > plugins/obora-plugin-custom-summary/src/index.ts << 'EOF'
// Minimal pattern plugin implementation.
// Matches the Obora pattern plugin shape:
// { name, version, type: "pattern", execute(...) }

type PatternRuntimeResult = {
  success: boolean;
  output?: unknown;
  error?: string;
};

export const customSummaryPlugin = {
  name: "custom-summary",
  version: "1.0.0",
  type: "pattern" as const,

  async execute(context: {
    input?: unknown;
    config?: { style?: string; max_points?: number };
  }): Promise<PatternRuntimeResult> {
    const style = context.config?.style ?? "concise";
    const maxPoints = context.config?.max_points ?? 5;

    return {
      success: true,
      output: {
        summary: `Generated by custom-summary plugin (style=${style}, max_points=${maxPoints}).`
      }
    };
  }
};

export default customSummaryPlugin;
EOF
```

This follows the runtime plugin contract (`name`, `version`, `type`, and `execute`).

---

## Step 3) Build the plugin package

```bash
cd plugins/obora-plugin-custom-summary
npm install
npm run build
cd ../../
```

You should now have compiled output in:

- `plugins/obora-plugin-custom-summary/dist/index.js`

---

## Step 4) Use the plugin in a workflow

Let's create a workflow that references the custom pattern.

```bash
mkdir -p workflows
cat > workflows/custom-plugin-workflow.yaml << 'EOF'
name: custom-plugin-workflow
version: "1.0.0"

steps:
  - name: collect
    agent: collector
    description: "Collect raw notes"

  - name: summarize-with-plugin
    agent: processor
    pattern: custom-summary
    depends_on: [collect]
    config:
      style: concise
      max_points: 5

  - name: finalize
    agent: writer
    depends_on: [summarize-with-plugin]
    description: "Create final deliverable"

recovery:
  summarize-with-plugin:
    on_fail: alternative
    fallback:
      name: summarize-fallback
      agent: processor
      description: "Fallback summary without plugin pattern"
EOF
```

---

## Step 5) Register and inspect plugin metadata

If your environment supports CLI plugin discovery, you can inspect:

```bash
obora plugin list
obora plugin inspect obora-plugin-custom-summary
```

If your runtime uses explicit registration in config/bootstrap code, register the built plugin module there before running.

---

## Step 6) Run and test

Run the workflow:

```bash
obora run workflows/custom-plugin-workflow.yaml
```

Dry-run validation first (recommended):

```bash
obora run workflows/custom-plugin-workflow.yaml --dry-run
```

What to check:

- `summarize-with-plugin` executes using `pattern: custom-summary`
- plugin output includes `style` and `max_points`
- if plugin execution fails, fallback step is used
